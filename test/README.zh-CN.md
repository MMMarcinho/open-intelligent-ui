# 组件可用性展示

启动：

```bash
npm install
npm run dev
# 打开 http://127.0.0.1:5173/test/
```

当前 Mac 也可打开正在运行的静态构建：`http://127.0.0.1:4173/test/`。

页面从 `protocol/registry.ts` 读取全部 61 个组件名，按文字、布局、交互、可视化、媒体、宿主分类。页底的“参考清单 → 展示项覆盖表”逐项链接到实际卡片，子组件会放入必要的父容器展示。每张卡显示名称、可用状态、属性/变体、最小用法及实际效果。

展示数据由 `gallery-data.ts` **直接构造标准 AST**，然后交给 React 渲染层；此页面不使用 DSL 解析器，因此可以先检查组件本身。切换 Studio/Citrus、浅/深色不会重置当前输入状态。边界菜单有标准、长文本、空值、禁用；切换边界会明确重建样例实例。输入、按钮、选择、复选框、滑块、轮播等可以直接操作，并显示当前值或点击次数。

状态解释：本地可用表示当前有可操作的参考实现；一般宿主能力需要真实资源、权限或服务合同，卡片显示未配置及原因；`svg` 明确未支持。`WritingBlock` 因编辑和保存合同未知，归入宿主能力。`AppBlock` 在画廊没有内容授权，仍显示未配置；工作台的两份已审阅样本可手动运行于隔离宿主。图表卡展示四种本地类型，不调用远程服务。

这张覆盖表只保证组件名称有可见展示入口，不等于实现与原参考环境完全一致。自动覆盖检查位于 `gallery.test.ts`。

静态逐项表见 [COVERAGE.zh-CN.md](COVERAGE.zh-CN.md)，可运行 `npm run gallery:coverage` 从注册表重新生成。
